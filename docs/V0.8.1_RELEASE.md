# CtrlSpeak 0.8.1 — Live shortcut and unobstructed terminal input

## Requested changes

- Recognize the default **Left Ctrl + Right Ctrl** Live start shortcut when
  pynput reports the left/default key as generic `Key.ctrl`, not only `Key.ctrl_l`.
  Press both keys and release both. Live must still be enabled in Capture.
- Keep the Live status capsule **top-centred inside the active monitor's work
  area**, so bottom-aligned terminal and Codex CLI input remains readable while
  phrases arrive. Hold and Hands-free retain their established bottom position.

This is a patch on `codex/dictation-modes-v0.8.1`, based on the verified 0.8.0
release. It introduces no new mode, provider, endpoint, permission or model.
The 0.8.0 release/tag/assets and signed 0.7.7 rollback target remain unchanged.

## Implementation and regression scope

The keyboard-name adapter and pure gesture recognizer now share the generic
Control-to-left convention. Right Ctrl remains distinct. Existing Ctrl+C/V and
other editing chords still invalidate the start gesture; synthetic-key filtering,
hold cancellation, release barriers and mute/delivery safeguards are unchanged.

Regression cases cover generic and side-specific Control names, both press and
release orders, Right Ctrl becoming a committed Hold before the chord, and the
full controller-to-monitor activation path. A separate Windows subprocess checks
real pynput key objects without starting any keyboard hook or injecting input.
That proves the supported backend representation, not a recording of the user's
physical keyboard events; physical-key acceptance remains a user check.

Overlay placement is chosen before the window first appears, without activating
it. A reused capsule is re-anchored when the next capture changes mode, preserving
top position through Live mute/editing/finishing and the final result. It is not
repositioned on every animation frame. Hold/Hands-free return to bottom placement.
Geometry respects taskbar work areas, scaling and negative-coordinate monitors;
very short work areas favour the actual top edge instead of a large top gap.

## Deployment and rollback

Use the existing signed coordinated release pipeline: Windows/Linux package
checks, immutable five-asset manifest/signature set, gateway/Ubuntu worker/Nova
helper activation and synthetic canaries before publication. Only version
metadata changes on the backend/helper; their API and provider logic is unchanged.
Nova's Hermes service needs no restart.

The Windows desktop/laptop install remains a user action through **Check for
updates**. Do not replace or restart the user's active desktop application.
**Updates → Roll back to 0.7.7** retains settings and saved credentials. Older
0.7.7/0.8.0 desktop clients remain compatible with the 0.8.1 backend.
