# CtrlSpeak v0.7.2 — dismissible Midnight Signal surfaces

Date: 2026-08-18
Release type: patch hotfix
Target branch: `v0.7`
Target tag: `v0.7.2`

## 1. Purpose

v0.7.2 preserves the v0.7 Midnight Signal design, the v0.7.1 native-audio
safety fix, and the existing transcription/API behaviour. It corrects a
desktop usability defect found after installing v0.7.1: the compact tray panel
could be opened, but its borderless surface exposed no visible way to hide it.
The user could continue transcribing, yet the panel remained on screen unless
the process was stopped or an undiscoverable dismissal path happened to work.

This patch makes dismissal visible, predictable, keyboard accessible, and
strictly separate from quitting CtrlSpeak.

## 2. User-visible contract

The released desktop application must satisfy all of these conditions:

- The compact quick panel has an always-visible **Hide panel** button.
- Escape and the window-close protocol hide the quick panel.
- The native tray menu uses the truthful static label **Show / hide quick
  panel**; selecting it again toggles the panel closed.
- The full control center has **Hide to tray** in its persistent header and on
  the System page, so dismissal is available regardless of the selected page.
- Hiding either surface leaves the tray process, right-Ctrl hotkey, recording,
  transcription, update coordinator, and gateway configuration running.
- **Quit CtrlSpeak** remains the only explicit application-exit action.
- Repeated close/hide requests are safe, and reopening never leaves duplicate
  or orphaned panels.

The quick panel remains borderless and topmost while open. v0.7.2 does not add
standard window chrome merely to obtain a close button; it adds an affordance
inside the approved Midnight Signal hierarchy.

## 3. Threading and lifecycle rules

Tk ownership remains on the application UI thread. The native tray thread must
not inspect `Toplevel` objects, widget focus, or other Tk state. The action label
is therefore static. The tray callback only queues the toggle onto the Tk UI
thread and lets pystray manage its native menu on the tray thread.

Quick-panel close must:

1. invalidate capability-refresh work owned by that panel;
2. cancel its polling callback when present;
3. destroy only the panel window;
4. clear the owned window and callback references; and
5. remain harmless when invoked again after the panel is already gone.

The quick panel deliberately does not use `FocusOut` as a close trigger. A
focus-driven close can race the native tray context menu, refresh or destroy a
Win32 menu handle from the wrong thread, and turn a stale Hide selection into
an accidental reopen. Explicit Hide, Escape, the window-close protocol, and the
static tray toggle provide deterministic dismissal instead.

## 4. Preserved safety and compatibility boundaries

v0.7.2 must not regress the v0.7.1 PortAudio serialization fix. Windows cue
playback remains independent from microphone capture, and hiding a surface
must not start, stop, detach, or cancel a recording session.

There is no request/response schema, provider-routing, authentication,
correction, language-policy, credential-storage, database, or service-role
change. Existing v0.7 clients and integrations remain compatible. The server
package and runtime version advance only to retain the project's synchronized
desktop/gateway release identity. The Nova Hermes adapter does not require a
code change for this patch.

The mandatory headless checks are:

```text
python -m pytest -m core_headless
python -m pytest -q tests/core
python -m pytest -q server/whisper_transcription/tests
python -m compileall main.py utils scripts tests server/whisper_transcription

```

Focused regression coverage must prove:

- source-level presence of visible and keyboard dismissal affordances;
- idempotent quick-panel close without an application-quit call;
- correct cancellation of the panel-owned polling job;
- repeated Escape, window-close, and tray-toggle hide/reopen cycles;
- no cross-thread native-menu refresh or Tk visibility reads; and
- the native tray action has the static **Show / hide quick panel** label.

Metadata tests must reject a version/tag mismatch and verify AppStream, Windows
PE strings/tuples, server package/runtime, changelog, and this release contract.

## 7. Physical and packaged acceptance

Test the exact one-file Windows candidate, not only source mode:

1. Start v0.7.2 from the stable `CtrlSpeak.exe` path and open the quick panel.
2. Hide and reopen it with the visible button, Escape, the static native tray
   toggle, the window-close protocol, and the tray icon's default action.
3. Traverse all panel controls and confirm the Hide action remains keyboard
   reachable without relying on color or an unlabeled glyph.
4. Open the full control center from each supported path. Verify the header and
   System-page **Hide to tray** actions, then reopen the same single window.
5. Record and transcribe before and after each hide path. Confirm the process
   remains alive and no `_portaudio` or Tk cross-thread failure appears in the
   application log or matching Windows event-log window.
6. Repeat the supported tray interactions on Ubuntu/X11. A desktop shell with
   no compatible tray integration remains within the documented Linux limit.

Also update an installed signed v0.7.1 copy through **Check for updates** and
confirm the stable path, settings, native OpenAI credential, corrections,
models, and gateway selection survive.

## 8. Release and deployment procedure

After every automated and physical gate passes:

1. Commit and push the reviewed `v0.7` branch.
2. Create and push the immutable annotated `v0.7.2` tag.
3. Allow the release workflow to build Windows/Linux one-file artifacts,
   generate and sign the manifest, audit the complete five-asset set, and
   publish only after all gates pass.
4. Independently download all five assets and run:

   ```text
   python scripts/release.py verify --directory <dir> --tag v0.7.2
   ```

5. Back up the dedicated gateway source and SQLite database, deploy the
   version-matched server source without overwriting protected environment or
   token files, restart it, and verify authenticated health/capabilities report
   `0.7.2` with the same role, providers, correction count, and database
   integrity.
6. The Ubuntu GPU worker requires no code or configuration change for this
   desktop-only patch. Confirm its existing worker role, CUDA model, private
   listener, and real restricted-language route remain compatible.
7. Confirm Nova Hermes remains healthy through the unchanged gateway API; do
   not replace its host-specific adapter for this UI-only patch.

The desktop updater never deploys services. Gateway and worker updates remain
explicit administrative operations.

## 9. Rollback and immutability

If a packaged UI, real recording, signed updater, or deployment gate fails,
do not publish v0.7.2. Fix forward on the branch and rerun the complete affected
gate. If failure is found after publication, never move the tag or replace
assets; publish a later patch.

For a service regression, restore the timestamped source and matching database
backup together, preserve protected configuration, restart, and verify the
prior version and provider routes. An installed desktop candidate that cannot
produce its signed health receipt must be rolled back automatically by the
existing update helper.
