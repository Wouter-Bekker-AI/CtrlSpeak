# CtrlSpeak 0.7.7 — reliability and responsiveness

## Scope and compatibility

This patch keeps Midnight Signal, current provider preferences, saved credentials,
lossless FLAC, known-word corrections and the optional worker-GPU S1 pipeline.
The Windows desktop/laptop install through **Check for updates**. Do not manually
replace or restart the user's running desktop during the backend release.
Gateway, Ubuntu worker and external Nova helper deploy at one signed revision;
Hermes itself is not patched or restarted.

## Faster, safer insertion

On Windows, remote viewers use packets of at most 16 UTF-16 units with 20 ms pacing; local
console packets use 64 units with 5 ms pacing. Surrogate pairs are never split.
For 4,911 ordinary characters this changes deliberate remote pacing from about
49.11 seconds to 6.14 seconds. This is a deterministic batching calculation,
not a guarantee of AnyDesk end-to-end delivery or an interactive benchmark.

The 0.7.6 control-character/paragraph policy remains in both the coordinator and
adapter. Default formatting remains off. Focus changes, cancellation, a 30-second
insertion deadline, or incomplete/uncertain OS delivery stop insertion. Never
paste the entire transcript automatically after accepting a prefix. Copy-last
retains the intended text for deliberate recovery; inspect the target first.
Already accepted input cannot be undone by cancellation.
Linux receives bounded cancellation checkpoints, but does not gain Windows'
foreground-window guard in this patch.

## Remote cancellation and failure recovery

Remote transcription uses an owned asynchronous HTTP session with a three-second
connection limit, a 90-second read-inactivity limit and a 180-second overall
request budget. Cancellation closes/awaits network work instead of leaving a
hidden HTTP thread blocking the next recording. This cannot undo a request
already accepted by a provider or guarantee avoidance of its charge.
Windows uses its native Proactor network loop with thread-safe c-ares DNS.
A live WAN multipart probe caught an alternate-loop incompatibility before
publication; the real synchronous client entry point is now regression-tested,
and packaged Windows health verifies the native loop.

One failed recording, at most 100 MiB, may remain in this process's memory for
15 minutes so the user can explicitly **Retry** or **Discard**. It is not a
persistent voice-history feature and does not survive exit. New recordings,
expiry, cancellation and discard clear recovery state. Temporary files used by
an explicit retry follow the normal managed recording cleanup path. Python/OS
memory may have transient copies or paging; this is not encrypted secure-memory
storage or a guarantee of forensic erasure.

No automatic resubmission is performed. Explicit Retry may incur another paid
provider request. Insertion failures must not offer audio retranscription as a
solution: some text may already be present. Use Copy last transcription instead.
Retry uses a confirmation and a three-second focus delay so the user can select
the intended destination before output is inserted.

## Worker admission and routing

The worker admits one active operation by default; the gateway admits eight.
There is no unbounded inference queue. Busy/stalled state is additive under
health/capabilities; basic process readiness remains backward-compatible.
The gateway uses a short busy cooldown, distinct from the existing 30-second
offline circuit, then follows the selected provider order.
Worker/gateway response deadlines default to 75/150 seconds. Active-request
capacity is configurable with `CTRLSPEAK_MAX_ACTIVE_REQUESTS` (1–32), and the
deadline with `CTRLSPEAK_REQUEST_DEADLINE_SECONDS` (greater than 0, at most 600). Tiny
inference has a separate capacity of one. See the API guide for exact telemetry
field names and correlation headers.

Native inference is not killed by cancelling its waiting coroutine. The owning
task retains its permit and audio until real inference/cleanup completes.
This prevents false recovery, overlapping jobs and deleting a file still in use.
Observed caller disconnect/cancellation prevents starting a new fallback attempt;
an already-accepted provider operation can still finish and be billed. The
gateway also rejects overlapping uploads to its one-slot worker locally, before
another multipart body crosses the WAN. An expired upload cannot start inference.
An actually stalled worker can remain unavailable pending an operator restart;
other permitted providers remain usable. Provider-independent invalid audio is
not repeatedly sent down the fallback chain.

## Diagnostics and privacy

Processing stages and numeric timing metadata distinguish upload, backend work,
cleanup and insertion. Correlated failures contain safe categories and durations,
not provider keys or transcript contents. Existing private transcript auditing
continues under the 0.7.6 policy; no blanket history export is introduced.
Health responses include low-disk warnings. They do not delete files or pretend
to fix disk pressure automatically.

## Deployment and rollback

Follow the existing signed coordinated pipeline: tests, packaged codec checks,
signed draft audit, stage all mandatory hosts, preserve selectors/database,
activate, health/version checks and synthetic canaries, then public stable
publication. Existing 0.7.6 clients remain compatible during the transition.
Roll back source selectors, never restore an old database over newer corrections.

The obsolete gateway CPU S1 dependency was removed from its old systemd drop-in
and that unused service stopped; its configuration/model files remain intact.
A protected rollback copy is retained at
`/var/lib/ctrlspeak-deploy/ops-v077/s1-mini.conf.before`. GPU S1 is unaffected.

Ubuntu root storage is critically low. Deployment must recheck free space before
staging or unpacking an artifact. No unrelated projects, databases, recordings or
shared caches may be deleted to make this release fit. Broader disk remediation
is separate from this patch.

## Verification status

Local pre-release verification: 398 core tests passed (one opt-in GUI test
module skipped); 84 portable service tests passed. Eight Linux shell tests are
reserved for Linux CI. Release/build/deployment evidence is added after the
signed pipeline completes.
Automated insertion tests never type into an active user application. Real
AnyDesk/terminal acceptance remains a post-update user check: dictate a short
sentence first and verify that nothing is submitted automatically.
