# CtrlSpeak 0.8.3 — animated keyboard guide and patch-update trial

## Scope

Branch: `codex/keyboard-guide-v0.8.3`, based on the published 0.8.2 code and
verified release evidence. Add an instructional UI, not another capture engine.
Existing shortcuts, privacy gates, recording behavior, API endpoints, provider
selection, S1 cleanup and text-injection rules are unchanged.

The Windows desktop/laptop installation remains a user action through **Check
for updates**. Do not replace or restart the user's app. Coordinate the gateway,
GPU worker and Nova external helper through the existing signed fleet workflow;
no Hermes core patch, configuration change or restart is required.

## User experience

- Open **Guide** in the control center or **Animated keyboard guide** in Capture.
- Choose **Hold to Talk**, **Hands-free**, or **Live Dictation**. A native Canvas
  draws the keyboard, relevant keys, pressed states, simulated mic/waveform,
  example destination and a step timeline in the Midnight Signal palette.
- The first visit plays one finite Hold lesson; choosing a mode plays its lesson.
  Play/Pause, Replay and Previous/Next let the user review it deliberately.
- Show the saved primary/secondary keys, including F8/F9/F10 alternatives. Apply
  keys in Capture updates the guide; unsaved combo-box edits do not mislead it.
- Reduced motion disables automatic/timed playback and offers manually stepped
  still frames. Leaving the Guide tab pauses playback. Closing the control center
  cancels its one owned Tk timer; no background animation thread is created.
- Instructions and controls appear above the illustration so they stay reachable
  on short displays; the existing management-page scroll area exposes all notes.

The illustrations are vector/code-native; there is no downloaded animation,
large video, image-generation dependency or network required to read the guide.

## Instructional accuracy and safety

Hold: focus a destination, hold the primary key and speak, release to process,
then insert the final transcript. No hold-mode mute toggle is advertised.

Hands-free: two short isolated primary taps start recording on the second
release. The illustrated taps are 120 ms with a 100 ms gap, matching the real
gesture recognizer's sub-180-ms hold threshold and 300-ms double-tap window.
Tap secondary to mute; tap it again to resume. Tap primary to finish.

Live: press primary and secondary together, then **release both**. Either press
order works. Explain Windows-only opt-in and whether it is enabled. Stable
phrases arrive after speech pauses, not revisable word-by-word streaming. The
actual Live capsule remains at the top. Show mute/resume, editing/held results,
finish and processing. Explain possible per-phrase OpenAI charges.

All text inside the demonstration is a fixed example. **The guide does not
record, install hooks, inject keystrokes, read the clipboard/transcript, enable
Live, alter preferences or call any provider.** Controls operate only on the
illustration. The guide explicitly warns that real keyboard shortcuts still
control CtrlSpeak globally: practice in a destination text field, not the demo.
Safety notes explain isolated taps versus Ctrl+C/V editing chords,
Esc cancellation (which does not undo inserted text), pending-text inspection and
AnyDesk's inability to expose every remote caret change.

## Test and release approach

- Pure lesson/playback tests cover all three modes and every valid key pair,
  finite completion, pause/replay/seek, invalid keys/time, actual gesture timing,
  availability, reduced motion, visibility and timer cleanup.
- Native Tk QA iterates every frame, exercises remapping, timer progression,
  page-like visibility, reduced motion and reachable controls at two sizes.
  `scripts/preview_keyboard_guide.py --verify` uses an isolated temporary profile,
  never the user's saved settings. CI uses Xvfb on Linux.
- Packaged health checks import the guide/widget and exercise all lesson
  timelines without a display, microphone, real input or provider connection.
- Run the serialized core and API suites and Windows/Linux Python 3.11/3.12 CI.
- Build/sign Windows and Linux executables and direct patches from the verified
  published 0.8.2 bases. Roundtrip/hash-check each before signing metadata.
- Independently audit the exact public release set and use the **old 0.8.2
  updater code** to download/reconstruct a real public 0.8.3 patch on D:, without
  preparing installation handoff or modifying the user's running app.
- Stage all backend roles before activation, preserve correction rules, run GPU
  plus S1/OpenAI/Tiny/helper canaries, then publish and reconcile the Ubuntu
  desktop companion. Preserve signed 0.7.7 desktop rollback.

## User acceptance: 0.8.2 → 0.8.3

1. Install 0.8.2 first. A 0.8.1 updater cannot consume a patch; skipping directly
   to 0.8.3 is supported but downloads the full executable.
2. On the exact released 0.8.2 executable, Check for updates should offer 0.8.3
   as a **Differential patch from 0.8.2**, with the patch's network size.
3. Install it deliberately. It reconstructs/verifies locally, then follows the
   existing detached-helper atomic replacement/startup-health/rollback path.
4. In 0.8.3 Updates, inspect the last-transfer receipt/Copy diagnostics: version
   0.8.3, method delta, patch bytes versus full bytes. Open Guide and try each
   animated lesson. Confirm the installed capture modes still behave normally.

A changed/unsupported base, missing/corrupt patch or reconstruction failure may
use the full signed fallback. Cancellation/signature failure/insufficient space
stop safely. Network savings do not eliminate reconstruction/startup/rollback
storage: free several GB before installing.

### Independent old-updater/public-patch proof

The operator loaded `utils/update_manager.py` from the actual **v0.8.2 Git tag**,
with its updater version fixed to 0.8.2. The updater, native encoder/decoder
adapter and pinned-tool definitions are unchanged between the two tags; this
was checked with a Git diff, not assumed.

That old code discovered the public signed 0.8.3 release, selected the exact
0.8.2 Windows base, downloaded **only the 4,948,378-byte public patch**, and
reconstructed the exact 228,335,126-byte signed target. The reconstructed target
ran its frozen health check successfully, including all three guide lessons,
dictation safeguards, audio/request transport and native delta roundtrip.
The base hash was unchanged; there was **no desktop installation or helper
handoff**. Explicit signed 0.7.7 rollback discovery passed too.

This proves the previous updater can consume this real release. It deliberately
does not mark the user's Check for updates / install / receipt trial complete.
The app uses binary-megabyte formatting labelled MB, so its download prompt
should display approximately **4.7 MB** for the Windows patch.
