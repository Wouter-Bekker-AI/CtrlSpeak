# CtrlSpeak 0.7.5 — lossless transport and coordinated deployment

## Scope

Desktop/laptop PCM16 recordings become FLAC before upload, preserving every
sample. The gateway forwards the same file bytes to OpenAI or the Ubuntu GPU.
Nova's compressed Telegram clips pass unchanged; WAV inputs use the same shared
preparation component. No UI redesign, provider-policy change, credential reset,
database migration or S1 model change is part of this patch.

`audio_transport.py` is shared by the desktop, inference service and isolated
external helper. Its encoder bounds work, cleans temporary files, preserves the
source and falls back to WAV when encoding is unavailable/unhelpful. Local
decoding rejects malformed/excessive input before passing a decoded array to
Whisper. Tests compare actual decoded PCM bytes and model input arrays.

## Release transaction

The immutable `v0.7.5` tag identifies one Git commit. GitHub runs desktop/core
and Linux service tests, builds Windows/Linux packages and executes the actual
packaged FLAC self-test. The existing five public assets and schema-1 update
manifest remain compatible with 0.7.4. An **additive signed `deployment` section**
binds worker/gateway/helper versions, protocol 1 and exact Git revision to the
same release. This replaces the planning proposal for a separate deployment
manifest/source asset; source is checked out from Git at the signed revision.

The `ctrlspeak-production` environment restricts deployment secrets to release
tags. A dedicated expiring SSH key and WireGuard peer permit private SSH only to
the three required targets. Keys are not personal administrator keys. SSH host
keys are pinned; forced commands accept only a bounded, signed deployment
request. The host agent and its configuration are root-owned outside release
source. No public application or SSH port is opened.

1. Build, sign, create/reconcile draft, independently download/audit all assets.
2. Stage clean immutable source and codec tests on every mandatory host.
3. Preserve current selectors; consistently back up gateway SQLite without
   stopping writes. Source/models/credentials/current data remain in place.
4. Activate worker, gateway, then external Nova helper. CtrlSpeak systemd units
   allow 300 seconds for in-flight request drain (330-second stop budget).
   Service restart may briefly interrupt new transcription requests. Hermes is
   not restarted; its active tasks and conversation remain independent.
5. Verify live version, revision, protocol, provider canaries and helper sidecar.
6. On any activation/verification failure, attempt reverse-order rollback,
   including an ambiguously completed target; leave the draft unpublished.
   Report unreachable rollback targets explicitly. Never restore old SQLite
   over new corrections simply to roll back code.
7. Publish stable/latest only after the required backend gate passes.
8. Reconcile the inactive Ubuntu desktop companion using the signed public
   Linux asset; retain its prior executable. This post-publication client step
   is distinct from the mandatory server gate and must be reported if pending.
9. Windows desktop/laptop update through the user's **Check for updates** action.
   An offline laptop is pending, not falsely claimed updated.

## Operations and rollback

Host receipts are retained under the configured deployment state directory,
one directory per exact commit. Gateway state is `/var/lib/ctrlspeak-deploy`;
user-host state is `~/.local/state/ctrlspeak-deploy`. `selector-before.json`
records the prior code selector, and the gateway transaction includes a
consistent protected corrections backup. Existing v0.7.4 Git checkouts and
model/runtime environments remain available.

The root-owned endpoint is `/usr/local/lib/ctrlspeak-deploy/deploy_host.py` with
host-specific `/etc/ctrlspeak-deploy.json`. It supports only signed stage,
activate, verify, canary, rollback and Ubuntu desktop reconciliation actions.
One nonblocking lock per host prevents concurrent deployment processes.
Subprocesses have deadlines and process-group cleanup. Signed code checkouts
must be clean; unexpected local edits block rather than being overwritten.

The CI private peer is `10.83.233.250/32` on Nova's existing `wg-fabric` hub.
Only private TCP/22 access to the three targets is added. Revoke its public peer
and `ctrlspeak-release-ci` authorized-key entries to disable CI access. The SSH
key expires 18 March 2027; rotate before then. Keep recovery keys local and
outside Git. GitHub environment secrets contain the CI configuration, dedicated
SSH key, pinned public host keys and role mapping—not user OpenAI credentials.

For a failed deployment, inspect the sanitized Actions receipt first, then the
protected host receipt/selector and exact service health. Re-run the **failed
job**, using the same immutable build artifacts, after fixing an operational
blocker. Never move a published tag or replace its signed bytes. Stage-only
failure leaves running versions unchanged. Publication failure after successful
activation leaves compatible backends upgraded and the candidate still draft;
reconcile and retry publication. Do not restart Hermes as a release-recovery step.

## Tests and remaining user acceptance

Automated checks cover bit-perfect mono/stereo sample preservation, compressed
pass-through, upload failure cleanup, preparation failure/cancellation, decoder
limits, multipart forwarding to both providers, correction/normalization
contracts, helper response selection, signatures and partial deployment rollback.
Live canaries use only the synthetic repository fixture, never a user's cached
voice note. OpenAI canaries incur a small ordinary transcription charge.

The Windows user-triggered installation remains a separate acceptance step:
check that 0.7.4 offers 0.7.5, install through the GUI, then record a short clip and
verify preferences/key/cleanup choice. Do not replace the running desktop exe
manually to bypass this check. The laptop may perform the same update later.
