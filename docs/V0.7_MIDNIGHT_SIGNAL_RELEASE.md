# CtrlSpeak v0.7.0 — Midnight Signal release contract

Status: approved visual direction and implementation/release acceptance record

Target branch: `v0.7`

Target release/tag: `v0.7.0`

Approved concept: [`design/v0.7.0-concepts/07-midnight-signal.png`](design/v0.7.0-concepts/07-midnight-signal.png)

This document is the durable product, engineering, deployment, and acceptance
contract for CtrlSpeak 0.7.0. It records what the approved **Midnight Signal**
direction means in a real application. Concept artwork is illustrative; only
working, measured application state may appear as live data.

## 1. Product outcome

CtrlSpeak 0.7.0 is a complete UI/UX overhaul without replacing the proven
record → transcribe → correct → insert workflow or the signed updater. It must
feel like one coherent desktop product rather than a collection of Tk dialogs.

The approved direction combines:

- Midnight Glass's clean, quiet recording and processing overlays;
- Signal Studio's useful provider, latency, microphone, route, and correction
  detail; and
- the spacing and hierarchy discipline demonstrated by Obsidian Halo and
  Carbon Instrument.

The rejected direction must not reappear: providers are not arranged in a
circle around a microphone. The processing animation may use an elongated
elliptical/orbital motion treatment, but provider order remains a readable
linear route and the application never predicts which provider will succeed.

## 2. Experience principles

### Calm by default

The ordinary hold-to-talk flow stays compact and non-disruptive. Operational
detail is available in the tray and control center, but it does not obscure the
active application or demand a decision for each recording.

### Detail with hierarchy

The selected route, provider readiness, microphone level, timing, corrections,
and update status are visible where they help. Advanced URLs, tokens, model
configuration, and failure details are progressively disclosed.

### Truth before spectacle

Provider names, fallback paths, milliseconds, dBFS, and status labels must
come from a well-defined measurement or authenticated response. Unknown data
is displayed as unknown/unavailable. Sample concept numbers never become UI
defaults.

### Fast perceived response

Right Ctrl feedback appears immediately. Recording level updates are smooth,
processing animation remains responsive while network/model work runs off the
Tk thread, and an offline Ubuntu worker continues to use the bounded gateway
probe/circuit behaviour rather than creating repeated UI stalls.

### Reversible user control

Mute, cue volume, reduced motion, route selection, language policy, correction
submission, credential storage, and updates remain explicit. Destructive or
security-sensitive actions require clear confirmation.

## 3. Visual language

Midnight Signal uses a dark graphite foundation rather than purple-heavy neon:

- deep charcoal/graphite surfaces with clear elevation;
- restrained cool cyan for focus and live activity;
- green for confirmed ready/success states;
- amber for fallback, warning, or requires-attention states;
- red reserved for actionable failures;
- off-white primary text and subdued secondary text with sufficient contrast;
  and
- consistent spacing, corner radii, dividers, and typography across tray,
  overlays, dialogs, and the control center.

Colour is never the only state carrier. Every state also has readable text and,
where appropriate, an icon/shape change. The release must be usable with OS
scaling and high-contrast-oriented colour perception.

## 4. Approved surfaces

### A. Tray quick surface

The tray is the daily control surface. Left-click opens the branded Midnight
Signal flyout when the platform supports it; right-click retains a dependable
native menu fallback.

The quick surface provides:

- CtrlSpeak 0.7.0 identity and current listening/recording/processing state;
- selected microphone and current/recent dBFS level;
- selected route and authenticated gateway state;
- provider readiness and the most recent safe measured latency detail;
- visible fallback/degraded status only when actually reported;
- Manage CtrlSpeak;
- Copy last transcript, disabled until a successful in-memory result exists;
- Submit correction…;
- Check/refresh gateway;
- Check for updates;
- audio-cue mute and volume access; and
- Quit.

The flyout must remain concise. Full URLs, tokens, long release diagnostics,
model downloads, and correction management belong in the control center.

### B. Recording capsule

Holding right Ctrl opens a slim, non-focus-stealing capsule on the active
monitor. It shows:

- a clear recording state;
- live elapsed time;
- selected microphone label;
- a waveform/level treatment driven by real PCM input; and
- a correctly labelled RMS dBFS value.

The dBFS meter uses 0 dBFS as digital full scale and a documented negative
floor for silence. It is not an SPL/noise-dose meter. Attack/release smoothing
may calm the display but must not invent non-silent audio.

### C. Transcribing capsule

Releasing right Ctrl transitions the same visual footprint into Processing.
The approved treatment is an elongated elliptical motion around the central
status—not a circular provider selector. It shows elapsed processing time and a
plain-language state while allowing cancellation when the runtime can safely
cancel.

Before a result, the surface may show the selected strategy but not a claimed
winning provider. After a result it may show:

- the actual `provider_used` display name;
- measured total route time;
- degraded/fallback state and ordered attempts; and
- success, cancellation, or a safe actionable error.

The success acknowledgement must be brief and must not expose transcript text
on screen by default.

### D. Control center

The management window becomes a deliberate Midnight Signal control center with
stable top navigation and coherent content cards. Its implemented information
architecture is:

1. **Capture** — listener state, Right Ctrl hotkey, microphone dBFS, last safe
   route result, overlay/reduced-motion controls, cue volume/mute, and preview.
2. **Transcription** — embedded/API selection, friendly provider strategy,
   ordered output languages, edit-feedback behaviour, and correction access.
3. **Routing** — gateway refresh/RTT, provider cards, truthful health/probe
   timing, secure OpenAI-key state, and the last measured attempt chain.
4. **Corrections** — searchable Heard → Output rules with add, edit,
   enable/disable, delete, scope, status, and priority.
5. **Updates** — current version, stable channel, signed-update phase/progress,
   release link, redacted diagnostics, cancellation, and restart/install.
6. **System** — selected microphone, local model/device/CUDA controls, masked
   gateway credentials, secure OpenAI-key persistence, runtime controls, and
   shutdown.

Navigation labels, card titles, status text, and action placement remain stable
while background work runs. One window instance is raised/reused rather than
duplicated.

## 5. State model

The user-visible state machine is:

```text
idle → recording → processing → success → idle
                  ↘ error     → idle
                  ↘ cancelled → idle
```

Allowed recovery includes starting a new recording after a terminal state.
Impossible or stale transitions are rejected. A monotonically increasing UI
revision prevents an older worker callback from overwriting a newer session.

Each immutable snapshot contains only operational presentation data:

- phase/headline/safe detail;
- elapsed duration and formatted label;
- smoothed dBFS and meter fraction;
- sanitized provider profile;
- sanitized attempt/category/timing values;
- degraded/cancel capability; and
- a bounded public error category.

It contains no transcript, audio, prompt, correction phrase, clipboard value,
HTTP header, credential, or arbitrary server message.

## 6. Truthful telemetry contract

CtrlSpeak distinguishes the following values:

| Label | Authority | Meaning |
| --- | --- | --- |
| Microphone dBFS | Desktop PCM stream | Smoothed RMS relative to digital full scale. |
| Health probe | Gateway | Duration of the bounded worker `/health` probe. |
| Probe age/cache/circuit | Gateway | Age and remaining fast-failover state. |
| Provider attempt | Gateway | Time spent attempting one provider. |
| Worker inference | Ubuntu worker | Time around model inference only. |
| Route total | Gateway | Time from route start to success/exhaustion. |
| Desktop elapsed | Desktop monotonic clock | User-facing session time, not server inference. |

Rules:

- `provider_used` is displayed only from the accepted response.
- Attempts retain server order and safe outcome/category values.
- Millisecond values must be finite and non-negative.
- Missing/unsupported values display `—` or **Unavailable**, not zero.
- Desktop elapsed time cannot be labelled inference, probe, or gateway latency.
- Readiness from capabilities is not proof that a later request used that
  provider.
- A strategy is user intent; `provider_used` is observed outcome.
- Fallback/degraded presentation requires actual response metadata.
- Raw server messages and unexpected category strings are reduced to a bounded
  safe UI vocabulary.

The v0.7 gateway advertises telemetry-family support and adds optional:

- provider `health` probe/cache/circuit values;
- `attempts[].duration_ms`;
- worker-derived `attempts[].inference_duration_ms`; and
- top-level `routing_duration_ms`.

All additions are backward-compatible. Older clients ignore them; newer clients
show missing values honestly against an older compatible gateway.

## 7. Audio feedback

Audio is supportive, not punitive. Requirements:

- cues are synthesized/prepared off the critical UI path where practical;
- every cue remains within the documented peak ceiling;
- the saved user volume applies bounded linear gain without hard clipping;
- mute prevents playback immediately;
- gain processing does not change pitch or playback rate;
- processing uses one short finite cue and never an ambient loop;
- repeated sessions cannot stack orphan loops; and
- playback failure cannot block transcription or crash the UI.

Headphone acceptance begins at a conservative system volume. The release must
not claim a medical hearing-safety guarantee; CtrlSpeak controls only its own
digital cue level, not device amplification or listening duration.

## 8. Accessibility and ergonomics

Release acceptance requires:

- logical keyboard focus order and visible focus indication;
- readable labels and state text independent of colour;
- no clipped controls at common 100%, 125%, 150%, and 200% scaling;
- an active-monitor overlay that does not steal focus from the target field;
- usable high-contrast-oriented colours and text/background contrast;
- a reduced-motion path that removes nonessential continuous animation while
  preserving state comprehension;
- predictable Escape/close/cancel behaviour;
- controls with meaningful disabled states; and
- no inaccessible circular provider-only navigation.

Headless tests cover state and formatting logic, but real Windows and Ubuntu/X11
desktop acceptance is mandatory for focus, scaling, tray, hotkey, microphone,
animation, sound, and active-field injection.

## 9. Privacy and security

Midnight Signal does not introduce transcript history. CtrlSpeak still retains
only the last successful transcript in memory for Copy last transcript, and
discards it at process exit.

The UI, logs, diagnostics, state snapshots, telemetry, and release artifacts
must exclude:

- audio bytes and temporary recording content;
- raw/corrected transcript text except where required for the existing explicit
  correction/feedback transaction;
- clipboard content;
- client/worker bearer tokens;
- OpenAI API keys or credential-file contents;
- prompts and known-word/correction phrases;
- request headers, cookies, or environment dumps; and
- raw upstream exception/response bodies.

Windows OpenAI credential persistence remains in Windows Credential Manager.
The gateway receives the key only on the applicable request and does not store
or forward it to the Ubuntu worker. UI status says configured/not configured;
it never reveals the key.

## 10. Persistence and compatibility

The upgrade preserves existing settings, API URL/identity, route, languages,
models, CUDA state, corrections, update journal, and credential-vault entry.
New visual/audio preferences use schema-backed defaults and atomic settings
writes. A missing new field must produce the safe default without damaging an
older settings file.

Recording files are generation-owned. Cancellation keeps a recorder busy until
it actually exits, stale workers cannot clear a newer generation, and insertion
is one atomic commit with cancellation. Shutdown signals the current
generation, waits only for a documented bounded interval, attempts exact-path
cleanup, and never blocks indefinitely on a provider. After the single-instance
lock is acquired, the next startup removes only crash-stale
`temp/recording-*.wav` files; it does not sweep unrelated temp content.

The stable installed filename remains `CtrlSpeak.exe` on Windows and
`CtrlSpeak` on Linux. 0.6.2 must discover the signed 0.7.0 release and update in
place with its existing verified helper and rollback path.

## 11. Gateway, worker, and Hermes deployment

The server package/runtime version is synchronized to 0.7.0 because the release
pipeline enforces one product version across desktop and maintained service.

Production responsibilities remain unchanged:

- dedicated OpenStack `CtrlSpeak`: authenticated gateway, corrections/audit,
  routing, request-scoped OpenAI proxy, and tiny CPU fallback;
- local Ubuntu PC: worker-only `large-v3-turbo` CUDA/float16 inference;
- Nova: WireGuard transport and Hermes, not a CtrlSpeak gateway/model host.

Deployment must preserve protected environment files, tokens, model caches, and
the gateway SQLite database. Take source and consistent database rollback copies
before replacing service source. Deploy/restart one role at a time and verify
private listeners, role/version, capabilities, correction counts, real GPU
transcription, telemetry, and fast fallback.

Hermes uses the existing authenticated `/v1/transcribe` contract and therefore
does not require a 0.7 code/config update when that contract remains compatible.
Its Nova-specific command adapter must be preserved: it loads the profile's
request-scoped provider/OpenAI credential and forwards them without gateway
persistence. Do not overwrite it with a generic adapter during server rollout.

If the Ubuntu worker is offline during release work, report it honestly. The
gateway may remain compatible and fail over, but the worker cannot be claimed as
deployed or tested until it is reachable.

## 12. Packaging and signed release

Required version identity:

- `utils/version.py`: `APP_VERSION = "0.7.0"`;
- server package version and `SERVICE_VERSION`: `0.7.0`;
- Windows file/product version: `0.7.0.0` / `0.7.0` strings;
- AppStream newest release: `0.7.0`;
- maintained spec: `packaging/CtrlSpeak_v0.7.spec`;
- annotated immutable Git tag: `v0.7.0`; and
- signed manifest/release title: `0.7.0`.

The tag workflow must produce exactly five public assets:

1. `CtrlSpeak-windows-x86_64.exe`
2. `CtrlSpeak-linux-x86_64`
3. `update-manifest.json`
4. `update-manifest.sig`
5. `SHA256SUMS`

The workflow builds natively, runs required tests, health-smokes packaged
artifacts, signs the canonical manifest, independently verifies the release set,
creates a draft, downloads/audits the five assets, and only then publishes the
stable/latest release. Never move the tag or replace consumed assets; ship a new
patch if a released defect is found.

## 13. Acceptance gates

### Automated

- full `core_headless` suite on Windows and Linux/Python 3.11 and 3.12;
- focused UI state, audio cue, backend telemetry, packaging, release tool,
  update manager, and update helper tests;
- deterministic recorder/cancellation races, generation ownership, delayed
  overlay dismissal, Win32 wrapper-HWND resolution, scaled flyout geometry,
  bounded shutdown, and stale-WAV cleanup tests;
- full maintained server suite;
- compileall and `git diff --check`;
- version/tag gate for `v0.7.0`;
- native Windows/Linux one-file build and packaged health receipt; and
- independent signed five-asset verification.

### Physical desktop

- tray flyout plus native fallback menu;
- single Midnight Signal control center;
- active-monitor/right-Ctrl recording capsule;
- real waveform, timer, and dBFS response;
- elongated processing animation with reduced-motion alternative;
- direct GPU, OpenAI, tiny, and controlled fallback result presentation;
- truthful missing/available timing labels;
- correction submission, Copy last transcript, and update actions;
- cue mute/volume/headphone check with no orphan loops;
- DPI, keyboard, focus, contrast, screen-edge, and multi-monitor checks;
- Windows injection and Ubuntu/X11 injection; and
- clean error/cancel/shutdown/WAV cleanup.

### Production services

- gateway and reachable worker report the intended 0.7.0 roles;
- corrections/audit and secrets survive deployment;
- provider-health capability fields are bounded and secret-free;
- real GPU request returns non-empty corrected restricted-language text;
- returned provider/attempt/routing/inference values match the real route;
- offline-worker probe/circuit produces fast controlled fallback; and
- Nova Hermes remains active and transcribes through the unchanged contract.

### Updater

- installed 0.6.2 discovers 0.7.0 via Check for updates;
- review/download/restart remain responsive inside Midnight Signal;
- same stable executable path reports 0.7.0 afterward;
- settings, credential, model, route, language, and corrections persist; and
- a deliberately unhealthy candidate restores/relaunches the prior executable.

## 14. Rollback

Desktop rollback is handled by the existing external updater helper and health
receipt. Server rollback restores the timestamped pre-0.7 source plus the
matching database/config snapshot, then re-verifies role, listener, health, and
correction inventory.

Visual failure that prevents settings or Quit from being reached is a release
blocker. The dependable native tray fallback and safe startup/error paths must
remain available even if enhanced presentation initialization fails.

## 15. Explicit non-goals

0.7.0 does not add transcript history, streaming transcription, audio playback
history, arbitrary provider URLs, public gateway exposure, a new correction
semantic engine, or a circular AI/GPU/Tiny microphone selector. It does not move
Hermes onto the desktop or make Nova a CtrlSpeak inference host.
