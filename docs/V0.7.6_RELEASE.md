# CtrlSpeak 0.7.6 — safe dictation, optional formatting, complete audit

## User behaviour

In **Transcription preferences**, enable **Use S1 Mini cleanup when using the
Ubuntu GPU** to reveal **Preserve paragraphs and line breaks**. The second
checkbox defaults off, including when upgrading an existing installation.

- AnyDesk, remote desktop or a terminal: S1 on, formatting **off**. Cleaned
  wording is inserted as one line. Only the user should submit the prompt.
- Word or another document editor: S1 on, formatting **on** to retain internal
  paragraph breaks. Do not use this option in terminals: those breaks can submit.
- S1 off or not actually applied: the formatting option is ineffective; ordinary
  ASR output is also protected as single-line dictation.
- Tabs become spaces in both modes. Escape, Backspace, NUL, C0/C1 command
  controls, lone UTF-16 surrogates and bidi overrides cannot reach injection.
  Normal international text, accents, emoji and joining characters are retained.
- Leading/trailing whitespace is removed in either mode; CtrlSpeak never adds
  an Enter after the text. Non-BMP Unicode uses proper UTF-16 surrogate pairs,
  preventing low-bit truncation into keyboard controls.
- Save applies the desktop formatting safety choice immediately, even to an
  in-flight transcription. Existing backend/S1 enable changes still require the
  restart indicated by the settings dialog. Preferences persist across restarts.

The policy runs on the desktop at insertion and again at the platform adapter.
The gateway does **not** flatten API output or change S1's prompt. This is not
a new transcript translation/normalization step and does not affect Nova's
Telegram paragraphs. The helper retains its existing validated output selection.

## Auditing and privacy

The gateway's protected `corrections.sqlite3` now keeps these fields per ID:

- `raw_text`: Whisper/provider output;
- `corrected_text`: deterministic dictionary/exact-override output;
- `s1_cleaned_text`: validated worker cleanup before gateway dictionary rules;
- `normalized_text`: optional cleaned variant actually returned by the gateway.

The two new nullable columns migrate additively. Old records remain null: their
historic cleaned text cannot be reconstructed. Existing rules and feedback are
preserved. S1 validation retains its existing outer-whitespace stripping; the
audit describes validated worker output, not unvalidated model token streams.
No new public history endpoint, authorization change or raw audio retention is
introduced. The worker continues to avoid a second persistent transcript store.

On Windows, `%APPDATA%/CtrlSpeak/logs/dictation-audit.jsonl` records raw,
corrected, cleaned, selected and **insertion** text, per-character control
counts, version, transcription ID, and attempt outcome. Linux uses the existing
CtrlSpeak config logs directory. JSON escapes all controls. At most three files
of approximately 2 MiB each are retained (rotation is size-, not age-based).
These are **private plaintext transcripts**: protect them, do not publish them
as routine diagnostics, and remove audit files if their history is unwanted.
Keys, tokens, headers and arbitrary response metadata are never copied there.

`attempted` records the planned adapter input, `adapter_returned` means the OS
adapter completed, and `failed_or_partial` does not claim that nothing was typed.
Neither success nor these logs can prove the remote application received every
character. Copy-last and edit feedback refer to the sanitized insertion text.

## Release / rollback

Use the existing signed GitHub coordinated release pipeline: tests, Windows and
Linux builds, draft/signature audit, worker/gateway/helper staging and backup,
activation, health/version checks and live route canaries, then stable publish.
The external Nova helper is reconciled without restarting or patching Hermes.
The Ubuntu desktop companion is updated from the same signed release. Windows
desktop and laptop remain user-updated through **Check for updates**.

Roll back code/selectors using the retained deployment receipts if required;
never restore an older SQLite database over newer corrections. The migration is
backward-compatible with 0.7.5. However, an old desktop has no injection safety
guard even when connected to a 0.7.6 gateway: update each desktop before relying
on this protection. Until then, disable S1 cleanup and restart the old client.

## Verification

Tests cover single-line and paragraph modes, all C0/C1 controls, Unicode
separators, emoji and low-bit CR regression, Windows AnyDesk/direct/fallback
paths, Linux clipboard paths, setting persistence, feedback/copy selection,
escaped/bounded audit records, additive migration and gateway newline retention.
No test types commands into a user's active terminal. End-to-end AnyDesk target
acceptance remains a user check after installing the signed desktop update.

Deployment evidence is appended after the release succeeds.
