## Agreed behavior

- Gateway remains the only client-facing API, routing and correction authority.
- Ubuntu worker optionally runs S1-mini after successful CUDA Whisper inference,
  within the same worker request. S1 runs in a warm, private CUDA llama.cpp service.
- Client/API `cleanup` is an explicit boolean, default false for compatibility.
  A persistent desktop checkbox opts into cleanup; the user's desktop will be
  configured GPU-preferred with cleanup enabled during deployment.
- OpenAI and gateway-tiny routes never call S1. Disabled cleanup does no cleanup
  work. Worker cleanup failure returns the successful Whisper result, without
  triggering another transcription attempt.
- Keep `raw_text` (ASR) and `text` (ordinary gateway-corrected text) compatible.
  Return optional `normalized_text` plus bounded normalization metadata, including
  requested/applied/status/model/device/location/duration. New clients select
  normalized text only on a valid applied response for their requested cleanup.
- Apply known-word rules to the selected cleaned variant at the gateway. Exact
  user-confirmed overrides take precedence. Never send OpenAI keys to the worker.
- Fail-open cleanup: bounded input/output, bounded queue and inference deadline,
  English-only, safe output checks. No gateway CPU cleanup, retries or model loads
  on the interactive path. Preserve worker health/circuit-break failover bounds.
- UI explains applied, off, unavailable, unsupported provider, unchanged, and
  timeout outcomes accurately. Preference survives an offline Ubuntu PC.
