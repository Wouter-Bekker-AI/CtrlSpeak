# CtrlSpeak v0.7.3 — desktop fidelity and clipboard reliability

Release date: 2026-08-18

Target tag: `v0.7.3`

Status: release-candidate contract. Publication, signed-asset verification,
packaged desktop acceptance, and production version synchronization must be
recorded only after those steps succeed.

## Purpose

v0.7.3 is a focused patch on the v0.7 Midnight Signal line. It fixes three
defects found after installing v0.7.2:

1. **Submit correction…** still opened the legacy fixed-height form and could
   hide its Submit button on a short or scaled Windows work area.
2. The recording and processing capsules used a generic line-drawn microphone
   instead of the proper CtrlSpeak microphone artwork.
3. **Copy last transcript** could report no usable clipboard value on 64-bit
   Windows.

This patch does not redesign provider routing, change transcription semantics,
alter the correction API, or introduce persistent transcript history. The
v0.7.1 PortAudio safety and v0.7.2 hide/dismissal contracts remain mandatory.

## Correction-submission dialog

The tray-launched correction form now belongs to the same Midnight Signal
visual system as the control center and quick panel. It provides:

- a responsive size derived from the active monitor's work area and current
  display scale;
- a vertically scrollable form body for the source phrase, replacement, scope,
  explanatory text, and the complete validated configured gateway URL;
- a non-scrolling footer that keeps live status, **Hide**, and **Submit
  correction** available when the body is scrolled or the work area is short;
- visible progress and bounded, fixed-category success/error summaries. Raw
  transport and validation details are not shown or logged; diagnostics retain
  only the exception category and completion outcome;
- Escape to hide, Ctrl+Enter or Alt+S to submit, and labelled keyboard access
  for the phrase and scope controls; and
- one reusable dialog instance that refreshes its runtime-pinned configuration
  when reopened and rejects stale asynchronous completion.

Validation still rejects empty or unchanged mappings. Submission remains a
background authenticated request to the configured gateway. The default scope
is the current authenticated identity; global scope still requires gateway
administrator permission. Embedded/local mode continues to explain that this
form creates gateway rules rather than pretending to store one locally.

## Recording and processing brand artwork

Both the live recording and processing phases use the proper CtrlSpeak
microphone artwork resolved through the platform-aware application asset path:

- packaged Windows uses the bundled ICO resource;
- packaged Linux uses the bundled PNG resource; and
- source runs resolve the same repository assets.

The overlay caches and retains its rendered image at the required physical
size. This is important because Tk canvas bitmap items are not resized by
canvas vector scaling and an unreferenced `PhotoImage` disappears. If the
asset cannot be decoded, the overlay must fail safely without bringing down
recording or processing.

The artwork change does not alter capture timing, dBFS calculation, provider
selection, animation truthfulness, reduced-motion behaviour, or the rule that a
provider is named only after the gateway reports the result.

## Windows Copy last transcript repair

The explicit tray recovery action remains memory-only: exactly one successful
transcript is retained until process exit. v0.7.3 repairs its Win32 staging path
by:

- declaring clipboard and global-memory API arguments and return values with
  pointer-sized ctypes types on 64-bit Windows;
- allocating and populating the movable Unicode buffer before clearing the
  existing clipboard;
- opening the clipboard with a valid invisible owner window for the
  `EmptyClipboard` / `SetClipboardData` transaction;
- serializing clipboard operations and retrying transient ownership contention
  for a bounded duration;
- transferring the global-memory handle to Windows only after a successful
  `SetClipboardData`; and
- reading the staged Unicode text back before reporting success.

If allocation, ownership, clipboard access, staging, or read-back fails, the
tray reports failure. CtrlSpeak does not claim the copy worked. Clipboard or
transcript contents must never enter diagnostics or logs.

This explicit recovery copy is separate from the temporary clipboard
transaction used for active-field injection. Existing non-text preservation
and Linux X11 clipboard contracts remain unchanged.

## Compatibility and service scope

The maintained server advances mechanically to v0.7.3 because the release
pipeline enforces one product version across the desktop and maintained
service. There are no route, OpenAPI schema, authentication, database,
correction, provider-cascade, language-policy, or deployment-configuration
changes.

For a production release, synchronize only the dedicated CtrlSpeak gateway's
service identity after a rollback copy and database backup. Verify authenticated
health and capabilities report version `0.7.3`, role `gateway`, the unchanged
provider strategies, and the unchanged correction inventory. The Ubuntu GPU
worker and Nova Hermes adapter require no source or configuration change when
their existing `/v1/transcribe` protocol remains compatible.

## Required physical and packaged acceptance

Headless tests cannot prove Tk layout on every monitor, ICO decoding in a
one-file build, native clipboard ownership, or microphone stability. Before
publication:

1. Build the exact one-file Windows and Linux candidates from clean release
   inputs and verify their product/version health receipts.
2. On 64-bit Windows at 100%, 125%, 150%, and 200% scaling where available,
   open the correction dialog on each monitor. Resize it to its minimum and
   confirm both phrase fields, scope, status, Hide, and Submit remain reachable
   by pointer and keyboard.
3. Submit a real user-scoped rule to the configured gateway and verify it is
   active without UI blocking or duplicate dialogs. Confirm the intended full
   gateway URL is visible and inspect the bounded status plus diagnostic log to
   ensure neither contains either phrase, a bearer token, raw gateway detail,
   or an authorization header.
4. Hold and release right Ctrl with a real microphone. Confirm the proper
   CtrlSpeak microphone artwork remains visible in recording and processing,
   and repeat the v0.7.1 50-cycle native-audio/event-log stress gate.
5. Produce a successful Unicode/multiline transcript, choose **Copy last
   transcript**, and paste it into Notepad and a browser field. Repeat under
   brief clipboard contention and confirm accurate success/failure feedback.
6. Re-run v0.7.2 quick-panel/control-center dismissal checks. Hide must remain
   distinct from Quit and must not interrupt capture or transcription.
7. Update an installed signed v0.7.2 copy through **Check for updates**. Confirm
   the stable executable path now reports v0.7.3 and retains settings, native
   credentials, models, logs, local correction data, and update history.

## Publication and rollback

Do not publish if any required platform build, version gate, signed-manifest
audit, physical correction/overlay/clipboard check, updater exercise, or
gateway acceptance fails. Fix forward on the release branch and rerun the
affected matrix.

After all gates pass:

1. commit and push the reviewed `v0.7` branch;
2. create and push the immutable annotated `v0.7.3` tag;
3. allow the release workflow to build, sign, independently redownload, audit,
   and publish exactly the five assets; and
4. independently verify the downloaded release set:

   ```text
   python scripts/release.py verify --directory <asset-directory> --tag v0.7.3
   ```

Never move the tag or replace consumed release assets. If a defect is found
after publication, issue a newer patch. The external updater's verified
previous executable remains the desktop rollback path; production service
source and database backups remain the gateway rollback path.
